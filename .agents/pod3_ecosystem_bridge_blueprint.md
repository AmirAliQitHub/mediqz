## 2. 24-HOUR CARNET DIAGNOSTIC WINDOW & EPISTEMIC DECAY PROTOCOL

### 2.1 The Epistemic Decay Law (Slide 12)
The psychological fidelity of a candidate's internal episodic memory trace decays exponentially following exam completion:
$$E(t) = E_0 \cdot e^{-\lambda t}, \quad \lambda = \frac{\ln(2)}{t_{1/2}}, \quad t_{1/2} \approx 8.5\text{ hours}$$
At $t = 24\text{ hours}$, cognitive resolution drops by over 85% ($E(24) \approx 0.14 \cdot E_0$). Beyond 24 hours:
- The candidate can no longer recall the intermediate mental branch points on their scratchpad.
- Time panic, stress doubts, and limbic hijacking cannot be reliably differentiated from genuine knowledge deficits.
- Reviewing an answer booklet degenerates into **Hindsight Bias** (Slide 85: *"I knew it all along"*), blinding the candidate to structural errors.

### 2.2 Pod 1-Aligned Non-Hostile Graceful Degradation
To protect candidate mental health while preserving data validity, the system **NEVER** locks the carnet from view. Instead, it deploys graceful telemetry degradation:
1. **Unrestricted Access:** The carnet, question answers, keys, percentages, and solutions remain 100% accessible to the candidate at all times.
2. **Telemetry State Transition ($t > 24\text{h}$):**
   - The analysis session badge automatically transitions from `VALIDATED_FORENSIC_AUDIT` (تحلیل معتبر بالینی) to `DECAYED_PASSIVE_TRANSCRIPTION` (تحلیل متأخر / رونویسی منفعل).
   - In longitudinal moving-average and trajectory algorithms (Slides 21–25), statistical confidence weighting is halved (`weight = 0.50`), preventing corrupted late-audit data from skewing predictive mastery indices.
   - Real-time in-session behavioral tags (`⟨ ش ⟩` stress doubt, `⟨ ز ⟩` time block) are disabled or archived as historical estimates because episodic memory of autonomic arousal has subsided.
3. **Gentle Reframing Banner (Slides 12 & 69):**
   ```
   ┌────────────────────────────────────────────────────────────────────────┐
   │ ⏳ تحلیل خارج از پنجره طلایی ۲۴ ساعته:                                 │
   │ جزئیات شناختی لحظه آزمون کم‌رنگ شده است؛ تمرکز روی حل عمیق تشریحی و   │
   │ ثبت تیپ تست‌ها در دفتر تیپ مسائل معطوف می‌شود.                        │
   └────────────────────────────────────────────────────────────────────────┘
   ```

### 2.3 Alternating Subject Sequence Rationale (Slide 16)
To prevent prefrontal working-memory fatigue and ego depletion during post-exam review, analysis order is strictly regulated:
$$\text{Analysis Sequence: } \mathbf{Strong_1} \longrightarrow \mathbf{Weak_1} \longrightarrow \mathbf{Strong_2} \longrightarrow \mathbf{Weak_2}$$
1. **Strong Subject 1:** Dopamine priming and self-efficacy anchoring.
2. **Weak Subject 1:** High-friction error confrontation while prefrontal working memory is fresh.
3. **Strong Subject 2:** Cognitive palate-cleanser and burnout breaker.
4. **Weak Subject 2:** Controlled diagnostic closure without despair.

## 3. THE SSC PROTOCOL (SYMPTOM $\to$ SYSTEMIC PATHOLOGY $\to$ CONCRETE ROUTINE)

### 3.1 The 4 Core Diagnostic Failure Clusters
Carnet bugs from the 85-slide workshop corpus are mapped into 4 mutually exclusive clinical clusters:

```
┌─────────────────────────────────────────────────────────────────────────────────────────────┐
│                                 THE 4 FAILURE CLUSTERS (SSC)                                │
├─────────────────────────┬─────────────────────────┬─────────────────────────┬───────────────┤
│ 1. Micro-Memory Deficit │ 2. Arithmetic & RAM     │ 3. Perceptual Decoy     │ 4. Sunk Cost  │
│    (حفظیات ریز و فرار)   │    (کندی محاسبات و رم)  │    (کوری ادراکی و دام)  │    (عدم اجکت) │
├─────────────────────────┼─────────────────────────┼─────────────────────────┼───────────────┤
│ • Slide 58, 60, 64      │ • Slide 36, 37, 41, 62  │ • Slide 38, 44, 57      │ • Slide 40, 48│
│ • Formula definitions   │ • Non-linear scratchpad │ • Top-down priming bias │ • Fixation >2m│
│ • Anatomy / Cell trivia │ • ACC restart loop      │ • Negative verb decoy   │ • Late blanks │
│ • Spaced Leitner fail   │ • Working memory bleed  │ • Skipping underlining  │ • Pacing panic│
└─────────────────────────┴─────────────────────────┴─────────────────────────┴───────────────┘
```

1. **Cluster 1: حفظیات ریز و فرمول‌های فرار (Micro-Memory & Volatile Formulas):**
   - *Symptom:* Lost marks in factual statements, capacitor definitions, endocrine trivia, or anatomical labels where solving time was under 45 seconds.
   - *Systemic Pathology:* Synaptic decay due to reliance on passive textbook re-reading; absence of distributed active retrieval.
   - *Prescription:* **روتین ۲۰ دقیقه‌ای شبانه جعبه لایتنر (Nightly Leitner Routine)** before sleep (22:30–22:50).
2. **Cluster 2: کندی پردازش عددی و سرریز حافظه کاری (Arithmetic Bottlenecks & RAM Bleed):**
   - *Symptom:* Lost marks in multi-step calculation problems (Stoichiometry, Coulomb's Law, Projectile Motion) characterized by abandoned intermediate derivations or time spikes.
   - *Systemic Pathology:* Disorganized scratchpad topology triggering Subthalamic Nucleus (STN) review signals and Anterior Cingulate Cortex (ACC) full-question restarts (90–120s lost per restart); low paperless mental calculation agility.
   - *Prescription:* **روتین ۲۰ دقیقه‌ای محاسبات سریع صبحگاهی (Morning Arithmetic Priming)** before breakfast (06:40–07:00).
3. **Cluster 3: کوری ادراکی و تله‌های طراح (Perceptual Blindness & Decoy Trapping):**
   - *Symptom:* Selecting the designer's attractive decoy option (گزینه دام); misreading negative qualifiers ("به‌جز", "نادرست").
   - *Systemic Pathology:* Top-down cognitive schema priming overriding bottom-up sensory encoding; omission of physical character-by-character underlining.
   - *Prescription:* **روتین ۱۵ دقیقه‌ای تحلیل دام‌داری (Trap Registry Deconstruction)** in the afternoon (17:00–17:15).
4. **Cluster 4: آبسشن تست و انحراف استراتژی (Question Obsession & Sunk Cost Anchoring):**
   - *Symptom:* Spending $> 120$ seconds on a single anchor problem in Booklet 2, starving 3 to 4 simple questions at the end of the section.
   - *Systemic Pathology:* Limbic emotional hijacking; refusal to execute the 120-second Ejection Protocol; cognitive tunnel vision.
   - *Prescription:* **روتین تست‌زنی سرعتی با اجکت خودکار (Timed 10-Question Sprint with Hard 90s Ejection Tripwire)**.

### 3.2 The Daily Prescription Cap & Pareto Prioritization Engine
To eliminate schedule spam and protect student executive bandwidth:
$$\mathbf{\text{Daily Prescription Cap: Maximum 1 Micro-Routine per Day (Exact 20 Minutes)}}$$

#### Mathematical Deficit Index ($D_{\text{cluster}}$):
$$D_{\text{cluster}} = \sum_{q \in \text{cluster}} \left( 4 \cdot \mathbb{I}_{\text{wrong}}(q) + 3 \cdot \mathbb{I}_{\text{blank}}(q) \right) \times W_{\text{subject}}$$
Where $W_{\text{subject}}$ is the subject's national Konkur weight (Biology: 12, Chemistry: 9, Physics: 7, Math: 7).

#### Deterministic Selection Rule:
$$\text{Cluster}^* = \arg\max_{c \in \{1, 2, 3, 4\}} D_c$$
The engine identifies the **single vital 20% systemic root cause** that generated the greatest mark deficit and prescribes **STRICTLY ONE 10-day routine** (1 card per day across Days 2–10). If the top deficit index is below threshold ($D_{\text{cluster}} < 12$ points), zero routine cards are injected to avoid unnecessary friction.

### 4.2 Schedule Merging & Overlap Guard
When a new prescription is confirmed:
1. If the student has **zero active prescriptions**, the 10 daily cards are scheduled across Days 2 to 10 starting tomorrow.
2. If the student has **an uncompleted active prescription** from Exam $N-1$:
   - The UI presents an explicit choice:
     - `[جایگزینی هوشمند (Smart Replace)]`: Cleans incomplete previous cards and slots the new higher-priority prescription.
     - `[ادغام در روزهای جمع‌بندی (Merge into Buffer)]`: Retains the active daily routine and schedules the new topic as 3 intensive synthesis sessions during Days 11–13.
3. In both cases, **daily cards per date never exceed 1**, preventing calendar overcrowding.

## 5. DIRECT ROUTINEHUB INJECTION ARCHITECTURE

### 5.1 Polymorphic Execution (Zero `CoursePlayer` White-Screen Crashes)
In Mediqz, `user_routines` entries represent daily tasks. Masquerading clinical prescriptions as fake course IDs (`rx_exam`) crashes `useCourseStore.fetchCourseById()` with a 404 or white screen.

**The Solution:** An explicit schema discriminator in `user_routines`:
`routine_type TEXT NOT NULL DEFAULT 'course_part' CHECK(routine_type IN ('course_part', 'exam_prescription'))`

```typescript
// frontend/src/components/student/RoutineHub/RoutineHub.tsx
const handleStartItem = async (item: RoutineItem) => {
  if (isFuture) {
    showFutureLockToast();
    return;
  }
  
  if (item.routine_type === 'exam_prescription') {
    // Dedicated prescription execution path: ZERO touch of useCourseStore!
    openPrescriptionModal({
      id: item.part_id,
      examId: item.course_id.replace('prescription_', ''),
      title: item.part_title,
      type: item.extra_payload?.type || 'morning_arithmetic',
      topics: item.extra_payload?.target_topics || [],
      dosageMinutes: item.slide_count || 20,
    });
    return;
  }

  // Standard educational course flow
  await fetchCourseById(item.course_id);
  startPartPlayer(item.part_id);
  setActiveTab('player');
};
```

### 5.2 `PrescriptionRunnerModal.tsx` (Interactive Micro-Drill Modal)
- Mounted directly inside RoutineHub with high z-index.
- **For Morning Arithmetic:** Presents an interactive 10-problem scratchpad drill (fractions, stoichiometry ratios, decimal squares) with a linear scratchpad guide and 60-second countdown per item.
- **For Nightly Leitner:** Launches the Leitner review carousel with active recall flip animation and automated step updating (`step 1 -> 2`).
- Upon completion, atomically updates `user_routines.completed = 1` and `completed_at = datetime.now()`.

### 5.3 Idempotent Transactional Ingestion
The backend injection endpoint executes an atomic SQLite transaction:
1. Deletes any pending or draft routine cards for `course_id = 'prescription_<exam_id>'`.
2. Inserts exactly 10 rows into `user_routines` with computed Shamsi dates (`addDaysToShamsi(today, d)`).
3. Slots morning routines at `order_idx = 0` (top of daily checklist) and nightly routines at `order_idx = 999` (bottom of daily checklist).
4. Commits transaction and updates `user_exam_prescriptions.status = 'injected'`.

## 6. AUTOMATED INJECTION INTO INCORRECTS HUB & LEITNER ENGINE

### 6.1 Injection into Incorrects Hub (`eu_activity_logs`)
Every failed or blank question in the exam is synchronized into `eu_activity_logs`:
- `course_id`: `exam_<exam_id>`
- `part_id`: `subject_<q.subject>`
- `eu_id`: `q.utid`
- `status`: `'incorrect'` (if answered wrong) or `'null'` (if left blank)
- `user_answer`: Digit of selected option (`1`, `2`, `3`, `4`) or `'0'`
- `shamsi_date`: Current Shamsi date string
- Result: These items automatically appear inside `CourseMistakesModal.tsx`, enabling instant 1-click interactive re-testing and spaced replay.

### 6.2 Atomic Leitner Extraction Engine (Zero 140-Word Stem Dumping)
Standard Biology exam questions contain lengthy 80–140 word stems with 4 Roman-numeral statements. Dumping raw stems into Leitner cards causes cognitive overload and destroys flashcard retention.

**The Atomic Proposition Synthesizer:**
1. Formulates flashcard prompts with strict length constraints:
   $$\text{Word Prompt: } \le 12 \text{ words}, \quad \text{Answer: } \le 15 \text{ words}$$
2. Formatting pattern:
   - `word` (Prompt): `[مبحث] • [صورت قید یا گزاره هدف]`  
     *Example:* `«زیست دوازدهم (رونویسی) • جهت حرکت رنابس‌پاراز روی رشته الگو»` (8 words).
   - `meaning` (Atomic Answer): `«از '۳ به '۵ (سنتز رشته جدید از '۵ به '۳ است)»` (11 words).
3. The UI micro-drawer allows 3-second user verification before saving.
4. Backend validation enforces an absolute ceiling: `len(word.split()) <= 20`.
5. Stored in `leitner_cards` with Fibonacci interval steps:
   $$\text{Intervals: } \{1, 2, 3, 5, 8, 13, 21\}\text{ days}$$

## 7. TRIPARTITE LOGBOOK ENGINE (خروجی‌های تحلیلی سه‌گانه) & 1-CLICK TELEPORTATION

### 7.1 The 3 Dedicated Logbooks (Slide 16)
To avoid generic, disorganized notes, all qualitative insights are quarantined into 3 specialized repositories:
1. **دفتر تیپ مسائل (Problem Type Logbook):**
   - Catalog of math/physics problem archetypes (e.g. نردبان تکیه‌داده به دیوار با اصطکاک, سینتیک درجه دو).
   - Standard flowcharting steps, fast heuristics, algebraic reduction models.
2. **دفتر دام‌داری (Examiner Trap Registry):**
   - Catalog of examiner deception tricks: semantic boundary conditions, negative syntax traps, deceptive unit conversions, decoy options.
3. **دفتر نکات مبحثی (Subchapter Margin Annotations):**
   - Precise theoretical nuances mapped directly to textbook chapter codes (e.g. زیست ۱۱ فصل ۴ گفتار ۲).

### 7.2 Zero DOM Bloat: Single Shared Lazy Drawer Architecture
Rendering 3 buttons on every question across 140 questions creates 420 DOM nodes, degrading mobile performance.

**The Solution:**
1. In `QuestionJournalView.tsx`, questions are viewed in active single-card focus mode (`selectedQuestionIndex`). In the action bar, there is ONLY **ONE single compact button**:
   `[ 🔖 ثبت در دفاتر تحلیلی ]` (1 DOM node).
2. **Single Lazy Drawer at DOM Root:**
   A single instance of `TripartiteLogbookDrawer.tsx` is mounted at the root of `TahlilHub`:
   - Managed via Zustand slice: `{ isLogbookOpen: boolean, activeLogbookQuestion: ExamQuestion | null }`.
   - Contains a sleek 3-way segmented control: `[ ⚡ تیپ مسائل ] | [ 🪤 دفتر دام‌داری ] | [ 📖 نکات مبحثی ]`.
   - Auto-fills the question's diagram URL, topic title, and key proposition.
   - Saves to `user_logbook_entries` with zero lag and 60fps mobile scrolling.

## 10. ZUSTAND STORE SLICES & STATE MACHINES

### 10.1 Prescription Store Slice (`frontend/src/store/usePrescriptionStore.ts`)
```typescript
import { create } from 'zustand';
import { api } from '../services/api';

export interface PrescriptionData {
  type: 'morning_arithmetic' | 'nightly_leitner' | 'trap_logbook' | 'timed_ejection';
  title: string;
  symptom: string;
  pathology: string;
  action: string;
  dosage_minutes: number;
  frequency_days: number;
  preferred_slot: 'morning' | 'afternoon' | 'night';
  target_topics: string[];
}

interface PrescriptionState {
  activePrescription: PrescriptionData | null;
  status: 'idle' | 'loading' | 'pending' | 'injected' | 'error';
  errorMessage: string | null;
  isModalOpen: boolean;

  fetchPrescription: (examId: string) => Promise<void>;
  injectPrescription: (examId: string) => Promise<boolean>;
  setModalOpen: (open: boolean) => void;
  resetPrescription: () => void;
}

export const usePrescriptionStore = create<PrescriptionState>((set, get) => ({
  activePrescription: null,
  status: 'idle',
  errorMessage: null,
  isModalOpen: false,

  fetchPrescription: async (examId: string) => {
    set({ status: 'loading', errorMessage: null });
    try {
      const res = await api.get<{ prescription: PrescriptionData; status: string }>(
        `/exams/${encodeURIComponent(examId)}/prescription`
      );
      set({
        activePrescription: res.prescription,
        status: (res.status as any) || 'pending',
      });
    } catch (err: any) {
      set({ status: 'error', errorMessage: err.message || 'خطا در بارگذاری نسخه آزمون' });
    }
  },

  injectPrescription: async (examId: string) => {
    set({ status: 'loading' });
    try {
      await api.post(`/exams/${encodeURIComponent(examId)}/inject-prescriptions`, {});
      set({ status: 'injected', isModalOpen: false });
      return true;
    } catch (err: any) {
      set({ status: 'error', errorMessage: err.message || 'خطا در تزریق نسخه به روتین' });
      return false;
    }
  },

  setModalOpen: (open: boolean) => set({ isModalOpen: open }),
  resetPrescription: () => set({ activePrescription: null, status: 'idle', errorMessage: null }),
}));
```
